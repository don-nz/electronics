Step through together and compare how many bits change at once. Standard binary can flip two or three bits in the same step (worst case at 011→100 and 111→000) — Gray code always changes exactly one bit per step, which is why it avoids the encoder boundary-glitch problem shown in view 2.

Standard binary's boundary readout can jump to any of up to 8 possible codes when several bits change together (e.g. 011→100). Gray code changes exactly one bit at every step, so its boundary reading is always just the two adjacent codes — never anything else.
